# 阶段工程文档规范

每个里程碑在开始生产实现前，必须在本目录新增 `mN-<name>.md`。阶段文档既是设计审核材料，也是该里程碑的验收记录。

## 必填内容

```markdown
# MN: 标题

状态：Planned | In progress | Complete
负责人：
起止提交：
关联 ADR：

## 问题与目标
## 范围
## 非目标
## 当前代码与依赖
## 设计
## API/IR/schema 变化
## 迁移与回滚
## 测试计划
## 验收矩阵
## 实现结果
## 删除内容
## 度量变化
## 残余风险与后续任务
```

## 文档门禁

- `Planned -> In progress`：设计、非目标、测试计划和退出条件已经可以审核。
- `In progress -> Complete`：实现结果、命令输出摘要、真实验证、删除内容和残余风险已经填写。
- 影响公共协议、IR 基础结构、ClickHouse schema、分页语义、告警语义或迁移策略的决定必须关联 ADR。
- 仅属于局部实现且可轻易回退的决定记录在阶段文档，不滥用 ADR。

## 验证证据

阶段报告只记录可复现命令、fixture 或脚本路径，不粘贴大量一次性终端输出。至少包含：

- 单元测试和集成测试命令。
- ClickHouse 版本与 schema fingerprint。
- 真实 API 场景及结果摘要。
- 前端 build 和关键页面回归。
- 新增/删除 production LOC。
- 已知未覆盖分支和风险。
